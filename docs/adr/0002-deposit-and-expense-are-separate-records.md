# 存款與消費是兩種獨立紀錄，餘額為推導值

存款（成員注資進共同錢包）與消費（從錢包支出）看似同一種「交易」的正負兩面，但存款沒有分類與內容、也不該進入消費統計。決定以兩張獨立的資料表存放，餘額 = Σ存款 − Σ消費，每次計算、不另存。金額一律為正整數元，不允許小數、零或負數。

## Considered Options

- **單一交易表、正負金額**：省一張表，但所有統計都要過濾掉存款，且存款列的分類/內容欄位永遠為空。
- **另設「退款」概念**：退款極少發生，決定直接手動修改原消費金額，不引入第三種紀錄。

## Consequences

- 消費統計（甜甜圈圖、趨勢圖、分類明細）只查消費表，不需任何排除條件。
- 分類是資料庫 enum；新增分類要跑 migration `alter type ... add value`，同時在前端分類表加圖示與顏色（2026-09-20 加入「帳單」即循此路徑）。
- AA 對帳（各成員存款累計與差額）不在 v1 範圍，但兩張表都保留記錄者欄位，未來可加而不需改資料。
- 金額用整數避免浮點加總誤差；若未來需要小數，屬於破壞性 schema 變更。
